一、整体分层架构

自上而下：使用方 → 前端（nginx）→ 三个 Python 服务 → 共享库 → 数据层。所有 Python 服务复用同一份 common/ 代码。注意：在线聊天用的 IM 长连接跑在 backend-web 进程内；websocket 服务是另一条 App 同款通道，专职自动回复。

二、外部平台与第三方集成

系统本身不生产数据，全部依赖闲鱼平台接口；AI 与语音识别为可选增强能力。

三、模块交互流程

逐个模块的端到端调用链：谁发起、经过哪些服务与函数、落在哪张表、和闲鱼怎么交互。横轴为调用顺序，虚线框为补充说明。

1登录与鉴权

用户名密码登录 → 锁定检查 → 密码校验 → 签发 JWT → 后续请求逐层鉴权。

2账号接入（登录 → Cookie → IM 长连接）

两条登录入口产出的都是 Cookie；Cookie 落库后再换 IM Token、建长连接，前端才能订阅实时消息。

3在线聊天（实时消息收发）

接收链走 IM 长连接推送；发送链走 mtop 接口。两条链在数据库之外完全解耦，前端只认 WebSocket 事件。

4自动回复引擎（websocket 服务）

与在线聊天是两套独立长连接：这条是「App 同款通道」，专门跑 7×24 自动回复与自动发货，不依赖浏览器是否打开。

5订单同步与自动发货

订单由 scheduler 定时抓取，也可由 websocket 的付款消息即时触发；两者最终都收敛到「规则 → 卡券 → 发货 → 通知」。

6定时任务调度（scheduler）

所有「不用人盯着也要跑」的事都在这里；任务配置存库，可在后台「定时任务」页面开关与改周期。

7语音转文字（ASR）

浏览器录音 → 前端转标准 WAV → 后端按配置选本地模型或云端 → 文本回填输入框，最后仍以文本消息发出。

8商品发布与商品监控

发布是「素材 → 生成 → 调闲鱼发布接口」；监控是「定时搜索/采集 → 落库 → 命中规则后自动下单并通知」。

9分销与推广（promotion 子项目）

独立子项目，与主服务共用同一套 MySQL；主后台的「分销管理」只读展示并做配置，实际下单/结算在代理侧完成。

五、目录结构

核心backend-web/

FastAPI 主服务。app/api/routes/ 按业务拆分路由，app/services/ 放业务编排。

核心websocket/

闲鱼 IM 长连接与自动回复引擎，app/services/xianyu/ 为核心实现。

核心scheduler/

各类定时任务调度，依赖 common 的模型与服务。

共享common/

三个 Python 服务共用：ORM 模型、Pydantic schemas、DB 会话、闲鱼接口客户端、工具类。

frontend/

Vite + React 单页应用，src/pages/ 按模块划分页面。

launcher/

Tkinter 桌面 GUI 启动器，面向 EXE 分发场景（非 Docker 路线）。

windows-one-click/

Windows Docker 一键启动脚本与使用说明，供无技术背景的用户使用。

promotion/ · xianyu-mobile/

独立子项目：推广平台（前后端）、uni-app 移动端，不参与主链路部署。

六、语音转文字实现细节

最新加入的能力：浏览器录音 → 统一转 WAV → 后端本地模型识别 → 回填输入框 → 以文本消息发出。

  • 浏览器 MediaRecorder 录音后，由 frontend/src/utils/audio.ts 解码重编码为 16k/16bit 单声道 WAV，避免依赖服务端 ffmpeg。
  • 后端 POST /api/v1/chat-new/transcribe-audio/{account_id} 接收音频或音频直链。
  • 识别方式由系统设置 asr.provider 决定：auto有云端 Key 走云端，否则本地；local只用本地；cloud只用云端。
  • 本地模型走 common/utils/local_asr.py（faster-whisper，CPU int8），模型缓存在 HF_HOME 指向的持久化目录。
  • 转写结果回填到聊天输入框，用户确认后按普通文本消息发送——绕开闲鱼仅接受图片的上传通道。

七、已知边界

  • 发送语音消息暂不可用：闲鱼 PC 侧上传通道只做图片安全审核（传音频返回 PICTURE_NOT_SAFE），实测多种参数与路径变体均失败，需抓包确认 App 侧真实接口。语音转文字是绕开该限制的替代方案。
  • IM 长连接约 2~3 小时被服务端主动断开：现已由 20 秒健康巡检 + 指数退避重连兜住，进程重启后按「自动恢复清单」重建连接（2026-10-17 起）。
  • 网页 IM 通道对 APP 来源消息的推送不稳定：同一账号时好时坏，故系统内账号互发依赖应用层补偿；与闲管家等 App 通道工具相比，实时性天然差几秒。
  • 闲鱼接口存在账号级风控：FAIL_SYS_USER_VALIDATE 一旦出现，重试无效且会加重风控。主页/头像类接口已加熔断（连续 3 次失败熔断 10 分钟）与失败负缓存，宁可留灰占位也不连击。
  • 闲鱼商品页可 iframe 嵌入（响应头无 X-Frame-Options），但登录态归浏览器，系统数据库里的账号 Cookie 无法跨域注入。
