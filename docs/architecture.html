闲鱼自动回复系统 · 项目架构图

六容器微服务 + 共享库 + 外部平台集成，源码级架构总览

仓库：xiejinhe/xianyu-auto-reply · 部署形态：Docker Compose（也支持源码 / 桌面 EXE 启动器）

一、整体分层架构

自上而下：使用方 → 前端（nginx）→ 三个 Python 服务 → 共享库 → 数据层。所有 Python 服务复用同一份 common/ 代码。

二、外部平台与第三方集成

系统本身不生产数据，全部依赖闲鱼平台接口；AI 与语音识别为可选增强能力。

三、服务清单

docker-compose 一键拉起 6 个容器；也可源码方式逐个启动。

服务端口技术栈职责
frontend9000 → 80Vite + React 18 + TS + Tailwind + nginx 管理后台界面；nginx 托管构建产物并反向代理 /api、/ws
backend-web8089FastAPI + SQLAlchemy(async) + asyncmy 主 API：账号、商品、订单、在线聊天、系统设置、语音转文字、AI 配置

四、目录结构

核心backend-web/

FastAPI 主服务。app/api/routes/ 按业务拆分路由，app/services/ 放业务编排。

核心websocket/

闲鱼 IM 长连接与自动回复引擎，app/services/xianyu/ 为核心实现。

核心scheduler/

各类定时任务调度，依赖 common 的模型与服务。

共享common/

三个 Python 服务共用：ORM 模型、Pydantic schemas、DB 会话、闲鱼接口客户端、工具类。

frontend/

Vite + React 单页应用，src/pages/ 按模块划分页面。

launcher/

Tkinter 桌面 GUI 启动器，面向 EXE 分发场景（非 Docker 路线）。

windows-one-click/

Windows Docker 一键启动脚本与使用说明，供无技术背景的用户使用。

promotion/ · xianyu-mobile/

独立子项目：推广平台（前后端）、uni-app 移动端，不参与主链路部署。

五、在线聊天语音转文字链路

最新加入的能力：浏览器录音 → 统一转 WAV → 后端本地模型识别 → 回填输入框 → 以文本消息发出。

  • 浏览器 MediaRecorder 录音后，由 frontend/src/utils/audio.ts 解码重编码为 16k/16bit 单声道 WAV，避免依赖服务端 ffmpeg。
  • 后端 POST /api/v1/chat-new/transcribe-audio/{account_id} 接收音频或音频直链。
  • 识别方式由系统设置 asr.provider 决定：auto有云端 Key 走云端，否则本地；local只用本地；cloud只用云端。
  • 本地模型走 common/utils/local_asr.py（faster-whisper，CPU int8），模型缓存在 HF_HOME 指向的持久化目录。
  • 转写结果回填到聊天输入框，用户确认后按普通文本消息发送——绕开闲鱼仅接受图片的上传通道。

六、已知边界

  • 发送语音消息暂不可用：闲鱼 PC 侧上传通道只做图片安全审核（传音频返回 PICTURE_NOT_SAFE），实测多种参数与路径变体均失败，需抓包确认 App 侧真实接口。
  • IM 长连接约 2~3 小时被服务端主动断开，且断后不会自动重连，需要手动或补重连逻辑。
  • 闲鱼商品页可 iframe 嵌入（响应头无 X-Frame-Options），但登录态归浏览器，系统数据库里的账号 Cookie 无法跨域注入。
